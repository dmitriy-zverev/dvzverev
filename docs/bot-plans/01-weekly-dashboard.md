# Фича 1. Недельный дашборд редакции

Статус: план. Приоритет: P0. Основа: [общий план](README.md).

## Результат для владельца

На `/bot/` видны семь дней недели, все сообщества, будущие выпуски и фактические
отправки. За один экран понятно, сколько публикаций ожидается, что уже вышло,
что задержано и какие ошибки требуют действия. Нельзя принять пустой календарь
при сбое API за отсутствие запланированных постов.

## Интерфейс

| Область           | Содержимое                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------------- |
| Верхняя строка    | Неделя, часовой пояс, предыдущая/следующая, «сегодня», фильтр проекта                         |
| Сводка            | Материалы запланированы / готовы / вышли / задержаны / завершились ошибкой / исход неизвестен |
| Состояние сервиса | Heartbeat, время обновления данных, возраст последней синхронизации, паузы и cooldown         |
| Календарь         | День, время, сообщество, тип публикации, тема или «тема ещё не выбрана», текст/GIF, статус    |
| Ошибки            | Нерешённые инциденты вверху, включая старые вне выбранной недели; затем события недели        |
| Детали выпуска    | Бриф, готовый текст, медиа, версия промпта, модели, расходы, доставки, история событий        |

На мобильном — список дней с карточками, а не горизонтальная сетка с мелким текстом.
Статус передаётся словом и значком, цвет только дополняет смысл. Поиск и фильтры
сохраняются в URL: `/bot/?week=2026-10-05&project=things&status=retry_wait`.

Ссылка на VK появляется только при подтверждённом post_id. Удалённый по TTL
текст обозначается «содержимое удалено после 30 дней»; ошибку загрузки детали
нельзя показывать как удаление. Платная повторная генерация не выполняется при
обычном открытии карточки или обновлении страницы.

## Реестр планируемых публикаций

Новый `schedule_slots` материализует будущие слоты на 14 дней вперёд, показывая
по неделе. Уникальность `(project_id, destination_id, slot_utc)` предотвращает
повторы при каждом проходе планировщика. Выпуск связывает доставки разных площадок.

Поля плана: слот, проект, получатели, формат, ожидаемое медиа, внутренний бриф,
тема, состояние темы, версия конфигурации. Темы можно задать вручную; если
редакционный план отсутствует, UI честно показывает известный формат и неизвестную тему.
Будущие слоты не содержат выдуманные заголовки «как будто текст уже написан».

Первый релиз: редактирование темы/брифа до начала генерации, с optimistic locking
по `version`. Готовый материал при правке темы не перегенерируется автоматически.
Перенос, отмена, ручная отправка и разрешение `uncertain` — следующий отдельный
этап с явным действием оператора и аудитом; кнопка повторной отправки в MVP отсутствует.

Изменение расписания пересчитывает только будущие незапущенные слоты.
Начатые и завершённые сохраняют исходный снимок. Выключенный проект не создаёт
новые слоты, а его старая история остаётся видимой. Просроченный слот при
`missedSlots=skip` становится `missed`, а не навсегда «планируется».

## Статусы и ошибки

| Внутренний статус  | Что видит оператор | Правило                                            |
| ------------------ | ------------------ | -------------------------------------------------- |
| planned            | Запланирован       | Есть слот, текста может ещё не быть                |
| generating         | Готовится          | Идут текст/редактор/сцена/видео                    |
| ready              | Готов к отправке   | Текст сохранён, соблюдены правила медиа            |
| sending            | Отправляется       | Исход API ещё не подтверждён                       |
| retry_wait         | Задержан           | Следующая попытка в указанное время, причина видна |
| sent               | Опубликован        | Есть подтверждение и post_id/message_id            |
| failed / exhausted | Не опубликован     | Попытки завершены или произошёл терминальный отказ |
| uncertain          | Исход неизвестен   | Нужна сверка, автоматического повтора нет          |
| missed / cancelled | Пропущен / отменён | Отдельная причина, не входит в успешные            |

`paused` — состояние проекта/получателя, а не успешное завершение выпуска.
Статус материала агрегируется из доставок: например, «частично опубликован»
при одном `sent` и одном `failed`. Счётчики показывают обе сущности отдельно.

Ошибка содержит stage, код, безопасное описание, время, номер попытки,
связанные выпуск/получатель, recovery и следующий retry. Разделять:
«GIF не получилась, текст вышел», «резервная модель сработала» и
«пост не вышел». Старые ошибки сохраняются в истории даже после восстановления.
Группировать повторы в один инцидент с количеством, не превращая календарь в поток одинаковых строк.

## Данные и API — предлагаемый контракт

| Маршрут                                           | Назначение                                               |
| ------------------------------------------------- | -------------------------------------------------------- |
| `GET /bot/api/v1/overview?week&project`           | Сводка, дни, карточки, версии данных и состояние сервиса |
| `GET /bot/api/v1/editions/:id`                    | Материал и отдельные доставки                            |
| `GET /bot/api/v1/incidents?project&status&cursor` | Ошибки и активные инциденты                              |
| `PATCH /bot/api/v1/plans/:id`                     | Тема/бриф незапущенного слота, ожидаемая version         |
| `GET /bot/api/v1/projects`                        | Доступные проекты и их расписания                        |

Ответ недели собирается в одной read-транзакции и содержит `as_of`,
`data_version`, `scheduler_last_seen_at`, чтобы разные блоки не противоречили
друг другу. Нельзя синхронно вызывать VK/LLM из GET-методов: API читает локальные данные.
Pagination и диапазоны обязательны, весь журнал одним запросом не выдаётся.

## Фронтенд и доступ

Сохранить `output: static`. Страница `src/pages/bot/index.astro` формирует оболочку,
а небольшой модуль запрашивает приватный API. Это соответствует
[файловой маршрутизации Astro](https://docs.astro.build/en/guides/routing/).
Приватные данные не попадают в static HTML, сборку, sitemap или публичный JSON.
Отдельный layout кабинета не подключается в лендинг.

Авторизация: один владелец, пароль в защищённом server-env, hash пароля на сервере,
защищённая HttpOnly/Secure/SameSite cookie с ограниченным сроком. API проверяет
сессию на каждом запросе. Для изменяющих операций — CSRF/Origin-проверка и
ограничение частоты. Логин и ошибки авторизации журналируются без паролей.
`noindex` и скрытая ссылка не считаются защитой. Не включать публичную регистрацию.

При 401/403 показать вход/отказ, при сбое API — явную ошибку, при старых данных —
«данные устарели». Автообновление раз в 30 секунд только во вкладке на переднем плане,
backoff до 5 минут, кнопка обновления. Ответы с данными и сессиями — `private, no-store`.
Тексты показываются как plain text; HTML из VK/LLM не исполняется.

## Измеримые критерии готовности

- [ ] Все три проекта видны; недельное расписание «Кода» учитывает дни недели,
      остальные — 10:00 и 18:00. Даты UTC/Moscow и переход недели проверены фикстурами.
- [ ] В fixture с partial delivery и media fallback сводка совпадает с реестром:
      выход текста не показан как полный провал, `uncertain` не показан как `sent`.
- [ ] Restart не добавляет слоты/отправки; смена расписания не меняет завершённые записи.
- [ ] Неавторизованный пользователь не читает тексты, ошибки, статистику и API.
      Проверены CSRF, XSS, доступ к чужому ID и конфликт изменения version.
- [ ] Недельный API: p95 ≤ 300 мс на синтетических 100 проектах × 30 дней,
      тестовый профиль сервера и исходные замеры приложены к релизу.
- [ ] Ассеты кабинета: JS ≤ 60 KB gzip, CSS ≤ 25 KB gzip; неделя ≤ 150 KB JSON.
      Текст не загружает GIF целиком; медиа подгружаются по открытию карточки.
- [ ] На 390 px нет горизонтального overflow; клавиатура, фокус и статусы доступны.
- [ ] Лендинг сохраняет собственные текущие бюджеты; Playwright smoke и проверки
      существующего сайта проходят после добавления маршрута.
- [ ] При остановке API бот публикует по расписанию; UI явно сообщает о сбое.

Бюджеты — цели реализации, не результаты уже проведённых измерений.
