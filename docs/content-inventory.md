## 4. Собственные проекты

## 4.1. «Маяк»

### Подтверждено

- утилита для анализа сайта на безопасность;

### Роль проекта на лендинге

Первый кейс, который показывает инженерную глубину, безопасность и способность создавать инструменты, а не только CRUD-приложения.

### Черновой Surface/System-образ

```text
SURFACE:  адрес сайта → запуск анализа → отчёт с находками
SYSTEM:   обход → набор проверок → классификация → результат
```

Это визуальная гипотеза, а не описание подтверждённой архитектуры.

### Нужно уточнить

- какую именно угрозу или проблему решает утилита;
- CLI, web-интерфейс или оба варианта;
- поддерживаемые проверки;
- стек проекта;
- архитектура и особенные технические решения;
- есть ли GitHub/demo;
- можно ли показать реальный обезличенный отчёт;
- количество проверок, скорость или другие честные цифры.

### Черновой заголовок кейса

> «Маяк» — показывает уязвимые места сайта до того, как ими воспользуются.

Формулировку про уязвимости нужно подтвердить содержимым инструмента.

Формулировку о персонализации нужно подтвердить логикой продукта.

## 4.3. Recall

### Подтверждено

- сервис для самостоятельной подготовки к собеседованиям;
- обучение построено на карточках;
- используется интервальное повторение.

### Роль проекта на лендинге

Кейс, показывающий продуктовую механику, алгоритмическую логику и работу с долгосрочным пользовательским прогрессом.

### Черновой Surface/System-образ

```text
SURFACE:  вопрос → ответ → оценка → следующая карточка
SYSTEM:   история ответов → алгоритм повторения → дата следующего показа
```

Конкретный алгоритм и модель оценки нужно подтвердить.

### Нужно уточнить

- как создаются карточки;
- есть ли AI-генерация или проверка ответов;
- какой алгоритм интервального повторения используется;
- стек проекта;
- личная роль Дмитрия;
- стадия, пользователи и доступность demo;
- какие продуктовые показатели можно раскрыть.

### Черновой заголовок кейса

> Recall — возвращает нужный вопрос именно тогда, когда знание начинает забываться.
