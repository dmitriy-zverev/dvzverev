# Redis-очередь и восстановление публикаций — 7 октября 2026

Область проверки: недельное расписание, Redis runner, переходы генерации и
доставки, синхронизация кабинета и работа контейнеров на cloudru.

## Причины инцидента

1. В production `HTTP_PROXY` и `HTTPS_PROXY` указывали на `127.0.0.1:3129`.
   В контейнере никто не слушал этот порт. Запросы к OpenRouter и Telegram
   завершались `ECONNREFUSED`, генерация исчерпывала три попытки, уведомления
   также не доходили. Прокси заменён на достижимый адрес выделенного VPS.
2. Runner присваивал Redis-задаче статус по общему результату `publish()`.
   Этот результат мог относиться к предыдущему слоту. `already_processed`,
   `retry_wait` и наличие `postId` ошибочно превращали новую задачу в
   `generating`, удаляя её из due-очереди. Терминальные ошибки и завершение
   фоновых попыток не сверялись с конкретной Redis-задачей.
3. Новый scheduledTask имел приоритет над сохранённым job.slot. Бриф старой
   генерации не сохранялся и терялся при вызове без scheduledTask. Сам текст
   редакторского feedback генераторы форматов заменяли стандартным сообщением.

## Исправления

- Статус Redis определяется историей именно его slot: receipt, pending,
  uncertain, terminal failure. Orphan generating без работы возвращается в
  planned; неопределённая доставка не отправляется автоматически повторно.
- За один проход берётся одна задача проекта, состояние сверяется до/после
  обработки. Прогресс обычных фоновых повторов также отражается в Redis.
- Сохранённый job.slot имеет приоритет; редакторский task сохраняется в job
  и передаётся в промпт на последующих попытках.
- Кабинет показывает терминальные статусы; архивная неуспешная генерация после
  восстановления не делает подтверждённую публикацию частично неуспешной.
- Redis переведён с volatile allkeys-lru на persistent AOF, отдельный volume
  и noeviction. Существующие задачи перенесены без сброса очереди.
- Redis-подключение имеет ограниченные повторы и отключённую offline queue;
  процесс закрывает соединение при завершении, вместо ожидания Docker timeout.
- Ручное восстановление `retryGenerationSlot` сохраняет неуспешные записи и
  блокируется, если по слоту уже была доставка. История отправок не удаляется.

## Проверка

- Добавлены регрессии для чужого slot receipt, orphan generating, exhausted,
  uncertain, сохранения брифа между попытками и запрета повторного восстановления.
- Полный набор `tests/bot/*.test.mjs` прошёл в изолированном production-образе,
  без сети и production-секретов. Fixtures, отсутствующие в runtime-образе,
  были подключены только к тестовому контейнеру.
- ESLint изменённых модулей, Prettier и git diff --check прошли.
- Локальный Node 26.3.1 аварийно завершался в cabinet.test.mjs внутри native
  callback scope; тот же набор в серверном runtime прошёл.

Это исправление текущего инцидента, а не гарантия отсутствия всех будущих ошибок.
Redis AOF everysec допускает потерю последней секунды при аварии хоста;
источником подтверждения внешней отправки остаётся fsync-состояние доставки.
