# Статистика и экономика сообществ

Каждый проект хранит собственные `analytics.json` и `generation-costs.jsonl` рядом с `state.json`. Рабочие файлы и отчёты в `bot/data/` и `bot/content/` исключены из Git и Docker-образа. Метрики собираются каждый час; доставка постов использует отдельную историю и блокировку. Ошибки аналитики уведомляют владельца через Telegram и не приостанавливают публикации. Ожидаемый отказ метода для ключа сообщества сохраняется как ограничение доступа, а не как авария. Недоступные методы проверяются повторно через семь дней; принудительный сбор повторяет проверку сразу.

## Что доступно с нашими ключами

Проверено 6 октября 2026 для `dark-academia` (194579254) и `code-to-think` (242034586):

| Метод                                  | Результат                                                     |
| -------------------------------------- | ------------------------------------------------------------- |
| `groups.getById(fields=members_count)` | Работает: число подписчиков                                   |
| `groups.getMembers(count=1)`           | Работает: число участников; список пользователей не сохраняем |
| `wall.get`, `wall.getById`             | Ошибка 27: недоступно с авторизацией сообщества               |
| `stats.get`, `stats.getPostReach`      | Ошибка 27: недоступно с авторизацией сообщества               |

Официальная [схема методов stats](https://github.com/VKCOM/vk-api-schema/blob/master/stats/methods.json) указывает для этих двух методов пользовательский токен. Здесь используем только ключи сообществ; пользовательская авторизация для аналитики не подключается.

Охват — количество людей, просмотры — счётчик показов/просмотров; это разные показатели. Суммарный охват нескольких постов не равен уникальной аудитории всей группы. Недоступные значения записываются как `null`, а не как ноль. История подписчиков содержит последние 168 часовых снимков и до 730 дневных значений. Последний снимок также содержит до 90 недавно опубликованных ботом постов и ограничения API.

## Воронка

| Поле                    | Значение                                                           | Источник                                        |
| ----------------------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| `subscribers`           | Число подписчиков на дату наблюдения                               | VK; можно уточнить импортом                     |
| `postReach`             | Охват постов за указанный период                                   | Пока ручной импорт                              |
| `postViews`             | Просмотры постов за период                                         | Пока ручной импорт                              |
| `productLinkClicks`     | Переходы по товарным ссылкам                                       | Ручной отчёт источника продаж/переходов         |
| `orders`                | Оплаченные заказы, учитываемые в отчёте                            | Ручной импорт                                   |
| `orderRevenue`          | Сумма этих заказов, RUB                                            | Ручной импорт                                   |
| `averageOrderValue`     | `orderRevenue / orders`                                            | Расчёт; при отсутствии заказов `null`           |
| `commissionRevenue`     | Начисленная комиссия, RUB; допускаются отрицательные корректировки | Ручной импорт                                   |
| `commissionRatePercent` | `commissionRevenue / orderRevenue × 100`                           | Расчёт                                          |
| `generationExpenses`    | Расходы на текст, проверку, сцену, изображения и видео             | Сообщённая провайдером стоимость; ручная сверка |
| `otherExpenses`         | Реклама и другие учтённые расходы, RUB                             | Ручной импорт                                   |
| `profit`                | `commissionRevenue − generationExpensesRub − otherExpenses`        | Расчёт                                          |

Прибыль считается от комиссии, а не от полной стоимости заказанных товаров. `0` означает подтверждённое отсутствие значения; `null` — отсутствие данных. При неизвестных комиссии или расходах прибыль остаётся `null`. Поля партнёрского отчёта нужно согласовать по периоду, возвратам и статусу оплаты; бот не угадывает эти значения.

## Расходы на генерацию

Новые API-запросы записывают стоимость до проверки сгенерированного текста. Поэтому учитываются также превью, техническая проверка и оплаченные ответы, отклонённые редакцией. Для видео сохраняется ID задания, а обновления стоимости одного задания не суммируются повторно. При потерянном ответе или неизвестной стоимости сохраняется `null` и признак неполноты.

Для старых постов восстановлены известные расходы из истории доставки. Это нижняя граница: прежние тесты, превью и неудачные запросы могли не сохранить стоимость. Начало полного журналирования указано в `trackingStartedAt`. День начала и более ранние периоды требуют ручной сверки. `knownProviderUsd` — известная сумма, а не обещание полного счёта провайдера. Неизвестные платежи препятствуют расчёту прибыли по автоматическим данным.

Расходы провайдера записываются в USD. Для прибыли в RUB импортируйте `generationExpensesRub` из своей сверки либо `generationExpensesUsd` вместе с `usdToRub`. Бот не подставляет текущий курс и не смешивает валюты. Если разные записи периода имеют разные курсы, импортируйте итоговые расходы в RUB. Ручные расходы имеют приоритет над автоматическим расчётом.

## Ручной импорт

Шаблоны:

- `dark-academia.metrics.example.json` — «Конэсанс».
- `code-to-think.metrics.example.json` — «Код на подумать».

Скопируйте нужный шаблон в `bot/content/metrics-report.json`, укажите даты, стабильный `id` отчёта и заполните известные поля. Оставьте неизвестные поля `null`; не подставляйте нули без данных. Денежные поля в RUB имеют максимум два знака после запятой. Передаём только агрегаты, без персональных данных покупателей.

```sh
docker compose -f bot/compose.yaml exec -T poster node bot/run.mjs --project dark-academia --import-metrics /app/content/metrics-report.json
docker compose -f bot/compose.yaml exec -T poster node bot/run.mjs --project dark-academia --metrics-report 2026-10-06 2026-10-06
```

Для второй группы замените `dark-academia` на `code-to-think`. Без дат отчёт строится с начала текущего месяца до сегодня, по московскому календарю. Импортированные групповые отчёты должны полностью покрывать выбранный период, иначе агрегатные коммерческие показатели остаются неизвестными. Периоды не обрезаются автоматически: запрос внутри месячного импорта требует исходных дневных данных или отчёта за целый месяц.

Повторный импорт с тем же `id` заменяет запись, а не удваивает показатели. Другой `id` с пересекающимся периодом того же scope отклоняется. `scope: "group"` — итог группы; `scope: "post"` с числовым `postId` — данные конкретного поста. Данные постов выводятся отдельно и не прибавляются повторно к итогам группы.

```sh
docker compose -f bot/compose.yaml exec -T poster node bot/run.mjs --project dark-academia --collect-metrics
```

Эта команда делает только читающие запросы, сохраняет снимок и ничего не публикует.
